# DocPilot MVP 设计说明

## 1. 项目定位

DocPilot 是一个独立开发的企业文档智能问答与检索评测平台。Kotaemon 仅作为产品流程和行业功能参考；DocPilot 不复制其源码、品牌、文案或页面设计。

项目目标不是堆叠功能，而是形成一条可演示、可测试、可解释的完整链路：上传文档、解析切片、建立索引、检索与重排、生成带引用的回答，并通过评测页面观察检索质量。

## 2. 目标用户与核心问题

目标用户是需要从内部资料中快速查找答案的小团队成员。现有文件分散、人工搜索慢，而且普通大模型可能脱离资料编造答案。

MVP 解决三个问题：

1. 将常见文档转换为可检索知识库。
2. 回答问题时展示来源片段，让用户能够核验。
3. 展示检索分数、重排顺序和测试结果，帮助定位回答质量问题。

## 3. 方案选择

采用前后端分离的单体应用，而不是微服务或直接修改开源项目。

- 前端：React、TypeScript、Vite，负责知识库、文档、问答和评测界面。
- 后端：Python 3.11、FastAPI、SQLAlchemy，负责业务接口和 RAG 流程编排。
- 元数据：SQLite，保存知识库、文档、切片、会话和评测记录。
- 向量库：Qdrant，保存切片向量并执行相似度检索。
- 模型：阿里云百炼 OpenAI 兼容接口；`qwen-plus` 生成回答，`text-embedding-v4` 生成向量。
- 本地运行：Docker Compose 启动应用和 Qdrant；密钥只从 `.env` 读取。

该方案比纯 Gradio 更适合展示产品设计和前后端边界，又比微服务更容易在个人项目周期内完成和讲清楚。

## 4. MVP 功能范围

### 4.1 知识库与文档

- 创建、查看和删除知识库。
- 上传 PDF、DOCX、Markdown 和 TXT 文件。
- 展示等待处理、处理中、成功和失败状态。
- 解析文本，按固定长度和重叠窗口切片。
- 为切片生成向量并写入 Qdrant。
- 删除文档时同步删除元数据和向量。

### 4.2 检索问答

- 用户选择知识库后输入问题。
- 分别执行向量检索和关键词检索。
- 使用加权分数合并候选片段，并调用 Rerank 接口重新排序。
- 将前若干片段作为上下文交给大模型。
- 输出答案、引用编号、文件名和原文片段。
- 当最高相关度低于阈值时，不调用自由发挥式回答，明确提示资料不足。

### 4.3 检索调试

- 展示初始召回片段、向量分数、关键词分数、融合分数和重排后顺序。
- 支持调整 Top K、相关度阈值和向量/关键词权重。
- 参数只影响当前知识库的测试配置，不提供复杂的全局模型管理。

### 4.4 测试评测

- 用户录入问题、期望命中的文档和参考答案关键词。
- 批量运行测试集。
- 输出文档命中、关键词覆盖、拒答是否正确和总通过率。
- 失败项标记为未召回、排序靠后、回答遗漏、错误引用或错误拒答。

## 5. 明确不做

MVP 不包含注册登录、多租户、权限系统、网页抓取、OCR、GraphRAG、Agent 工具调用、计费和线上多人协作。这些功能不影响核心链路证明，暂不增加。

## 6. 核心数据流

### 文档处理

`上传文件 -> 保存文件信息 -> 解析文本 -> 切片 -> 批量生成向量 -> 写入 Qdrant -> 更新处理状态`

任一步失败都保留文档记录并标记失败原因，允许用户重新处理，不产生“界面成功但向量未写入”的假状态。

### 问答

`问题 -> 向量召回 + 关键词召回 -> 分数融合 -> Rerank -> 阈值判断 -> 生成回答 -> 绑定引用 -> 保存会话`

回答中的引用只能指向传给模型的片段。未达到阈值时返回资料不足，并保留调试结果供查看。

### 评测

`测试用例 -> 运行同一检索问答流程 -> 规则判定 -> 错误分类 -> 汇总结果`

评测复用正式问答流程，避免测试逻辑与真实产品行为不一致。

## 7. 主要页面

1. 首页：知识库列表、文档数量和最近更新时间。
2. 知识库详情：文件上传、处理状态和文档操作。
3. 问答页：对话区、引用卡片和原文查看。
4. 检索调试页：候选片段、分数、排序及参数设置。
5. 评测页：测试用例管理、批量运行和错误分类结果。

界面采用简洁的桌面端管理后台布局，不仿制 Kotaemon 的视觉样式。

## 8. 接口边界

- `/api/knowledge-bases`：知识库增删查。
- `/api/knowledge-bases/{id}/documents`：上传和查询文档。
- `/api/documents/{id}/process`：处理或重新处理文档。
- `/api/chat`：执行检索并生成带引用回答。
- `/api/retrieval/debug`：只返回检索和重排过程。
- `/api/evaluations`：管理测试用例并运行评测。
- `/api/health`：检查应用、数据库、Qdrant 和模型配置状态。

接口统一返回明确的错误码与用户可读信息，不把模型密钥或底层异常堆栈返回前端。

## 9. 测试与验收

每项后端行为先写失败测试，再实现最小代码使其通过。外部模型接口使用固定响应替身做自动化测试，另保留真实百炼连接的手动验收流程。

MVP 验收标准：

1. 能上传并成功处理至少三种文档格式。
2. 文档内问题能返回正确答案和可核验引用。
3. 文档外问题能拒答，不编造内容。
4. 调试页能解释片段从召回到重排的顺序变化。
5. 至少十条测试用例可批量运行并生成错误分类。
6. 后端自动化测试、前端组件测试和生产构建全部通过。
7. 新用户按照 README 能在本地完成启动和演示。

- 本地启动及环境变量说明。
